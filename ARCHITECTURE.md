# Architecture and limitations

## Navigation

Chrome's [declarativeNetRequest API](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest) supports persistent dynamic redirects even when the service worker is suspended. Each active domain generates an anchored, boundary-aware main_frame regex rule. The redirect uses a capture to preserve the original destination in the warning page fragment. Fragments are not transmitted to a server. Entries are bounded to 200, below the regex and unsafe dynamic rule ceilings. Rules are atomically replaced by Chrome after a successful storage write; storage and DNR are not one transaction. Failures are shown on extension pages and retried on startup or the next sync change. A small reconciliation window exists.

A higher-priority session allow rule matches an escaped exact URL and one tab ID. An alarm removes it in five minutes; closing the tab removes it as well. Session rules survive worker suspension but not browser restart. Alarms can run late when Chrome sleeps; while asleep no requests run, but a brief grace period on wake is possible. A new bypass in the same tab replaces its old bypass. URL fragments aren't network request components, so a fragment-specific bypass may fail closed; return without a fragment if needed. Redirect chains to other paths/domains can prompt separately, intentionally. No global disable switch.

Content scripts intercept ordinary primary, middle, and modified anchor clicks in capture phase and request the warning in the same/new tab. DNR handles address-bar entry, bookmarks, network redirects, new-tab destinations, and most script-driven network navigations. Content interception is supplementary, not the security boundary.

Limitations: Chrome internal pages, Chrome Web Store pages, extension pages, file URLs, non-HTTP schemes, embedded resource frames, browser download flows, POST navigations, prerender/cache/service-worker-served responses, and history restored from back-forward cache may not show a warning. POST can produce an unsafe-redirect error. Same-document SPA/history transitions make no network request and are not a fresh DNR interception. An already loaded blocked page isn't forcibly closed. Other extensions and enterprise policies may override behavior. Site-access restrictions can disable content scripts or redirects. Install/reload existing pages to inject scripts. Turning the extension off disables all protections.

## Links, Gmail, and Search

Observe only child insertion and href changes; changed subtrees feed a deduplicated queue. Processing yields every 300 anchors. A settings/list update rescans the page once. Only matching anchors are styled, never whole article containers or result cards. Original title attributes are restored when treatment stops. Hide can leave blank search snippets or a containing button's empty space: this is preferable to deleting surrounding page content. Large subtree enumeration still has a cost, but there is no polling or repeated full-page mutation scan. Closed shadow roots, non-anchor controls, canvas content, and unobservable custom navigation may not be marked. DNR still applies when a main-frame network request occurs.

Gmail conversations and Search results are treated through dynamically inserted anchors. Only recognized Google `/url` query destinations (and Google image result referrers) are unwrapped, with a strict HTTP(S), no-credentials parser and bounded depth. Ordinary direct Gmail links work; opaque tracking and shortened URLs are left as their visible destinations. No URL fetching or arbitrary query-parameter guessing. An opaque redirect may only be blocked when the browser reaches its final blocked destination. No claim is made to cover every Gmail tracking wrapper or every Search layout. Navigation remains domain based even when link markings are unavailable.

## Sync model

Chrome [storage limits](https://developer.chrome.com/docs/extensions/reference/api/storage) include 102,400 total bytes, 8,192 bytes per item, 512 items, 120 writes/minute, and 1,800 writes/hour. Records are versioned (`v:1`), reason lengths capped at 500 characters, and each domain stored separately under `e:<ascii-domain>`. Preferences have individual `s:` keys. Mutations are serialized by the service worker, not written directly by UIs. Bulk import/clear uses one set call; input keystrokes do not write. Quota exceptions are surfaced, never silently downgraded to unsynchronized local storage. There is no automatic rapid retry loop.

A persistent `d:<domain>` deletion token invalidates entries whose generation doesn't match it. New entries start with generation `''`; explicit re-adds copy the currently observed deletion token. Edits preserve their generation. A stale device updating a deleted entry therefore cannot resurrect it. Concurrent deletes with distinct tokens fail closed until an explicit re-add uses the winning token. Simultaneous active edits follow Chrome's per-key last-writer behavior. An explicit import counts as a fresh user decision and can re-add a deleted site. Sync is not a distributed transaction: a device may transiently display old data before tombstones arrive, and Chrome provides no cross-device compare-and-swap guarantee.

Deletion tokens are deliberately never garbage-collected: offline devices have no bounded stale horizon. Deleted entry payloads remain stored but inactive, and backups contain active entries only. Consequently a long-lived installation can exhaust sync capacity even with a small active list. The UI reports quota failures; export before migrating to a fresh extension identity if capacity is exhausted. Erasing tombstones in place weakens stale-update protection and isn't offered. Sync error status is local operational data, not an alternative database.

The schema reader rejects malformed and unknown versions without overwriting them. Version 1 is the initial schema; no speculative legacy migrations run. A future migration must preserve generations and deletion tokens, validate before writes, and reject unknown future versions. Backups explicitly require version 1. Domain storage is canonical ASCII IDNA, `www` folded, trailing root dot stripped; exact matching includes the www alias. Private suffixes protect independent hosted tenants. Public suffixes, IP literals, localhost, credentials, and invalid host labels are rejected.

## Verification scope

Unit tests cover domain/PSL/IDNA boundaries, redirect parsing, schema safety, deletion generations, imports, and rule construction. Chromium automation tests actual packaged UI and navigation behavior plus dynamic content and settings. Live multi-device Chrome Sync, authenticated Gmail, enterprise configurations, all cached navigation modes, and store review are not automated or certified. This is a personal preference utility, not a security or parental-control boundary.
